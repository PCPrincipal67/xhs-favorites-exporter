# Spec Delta

## Purpose

Observe pagination generated by the logged-in page without misrepresenting request failures or unknown continuation state as successful collection completion.

## ADDED Requirements

### Requirement: Validated passive response observation
The exporter SHALL observe page-generated pagination without replaying private API requests. It SHALL update records and pagination only after validating a successful HTTP status, valid payload structure, and successful business status when present. Network errors, aborts, timeouts, malformed payloads, HTTP failures, and business failures MUST NOT be interpreted as empty successful pages.

#### Scenario: HTTP rate limiting
- **WHEN** a relevant pagination request returns HTTP 429
- **THEN** the exporter leaves existing records and pagination intact and reports rate limiting

#### Scenario: Business failure within HTTP success
- **WHEN** a relevant request returns HTTP 200 with a failure business code
- **THEN** no records or pagination are merged and the failure is displayed

#### Scenario: Invalid or interrupted response
- **WHEN** relevant pagination returns malformed JSON or fails through a network error, timeout, or abort
- **THEN** it does not produce a successful page event or overwrite known pagination

### Requirement: Honest continuation state
The exporter SHALL distinguish known continuation, known exhaustion, and unknown continuation. Missing continuation metadata MUST remain unknown rather than become false. An empty page alone MUST NOT establish exhaustion unless the verified endpoint contract explicitly defines it that way.

#### Scenario: Absent continuation flag
- **WHEN** a valid response omits a verified continuation indicator
- **THEN** page_info.has_more is null rather than false

#### Scenario: Explicit final page
- **WHEN** a valid response explicitly indicates no more pages
- **THEN** page_info.has_more is false

### Requirement: Collection termination status
The exporter SHALL distinguish stopping for observed exhaustion, stopping for inactivity, and stopping for a pagination error. Relevant pagination failures SHALL stop automatic scrolling and preserve collected results for export or an explicit restart. Inactivity without confirmed exhaustion MUST NOT be described as a complete export.

#### Scenario: Idle stop without confirmed exhaustion
- **WHEN** collection reaches the bottom and the idle threshold while continuation remains unknown
- **THEN** scrolling stops with an inactivity status that does not claim completeness

#### Scenario: Pagination failure during collection
- **WHEN** a relevant request fails while automatic collection is running
- **THEN** scrolling stops with an error status and existing collected records remain exportable
